# CBB 文档规范

## 1. 一项 CBB 一个文档

每个 CBB 只维护一个文档：

```text
docs/cbb/<module>.md
```

- 文件名与 RTL 模块名一致。
- **不再拆分 README / design 两份文档**；`design` 相关内容作为同一文档中的章节存在。
- `docs/cbb/README.md` 只是文档规范与索引，不属于任何模块。
- CBB 进入开发时创建文档，不预先建空文件。
- 模板：[`_template.md`](_template.md)。

## 2. 章节要求

| 章节 | 简单 CBB | 复杂 CBB | 说明 |
|---|---|---|---|
| 1. 基本信息 | 必须 | 必须 | CBB ID、模块名、状态、版本等 |
| 2. 功能与范围 | 必须 | 必须 | 做什么、不做什么、典型场景 |
| 3. 端口表 | 必须 | 必须 | 方向、位宽、时钟域、说明 |
| 4. 参数表 | 必须 | 必须 | 默认值、合法范围、约束 |
| 5. 使用说明 | 必须 | 必须 | 时序/吞吐/反压/初始化/例化示例 |
| 6. 复位与 CDC | 必须 | 必须 | 复位策略、CDC 策略 |
| 7. 限制与注意 | 必须 | 必须 | 已知限制、不可用法 |
| 8. 验证状态 | 必须 | 必须 | 自检、TB、SVA、仿真器、未跑项 |
| 9. 微架构与数据流 | 可省略 | **必须** | 模块划分、框图、数据流、关键寄存器 |
| 10. 状态机 | 可省略 | **必须** | 无 FSM 时写“不适用”及原因 |
| 11. 时序、流水线与 PPA | 可省略 | **必须** | 延迟/吞吐/关键路径/面积功耗 |
| 12. 风险与未覆盖项 | 可省略 | **必须** | 风险、限制、未验证场景 |
| 13. 版本记录 | 必须 | 必须 | 版本、日期、变更、兼容性 |
| 14. 相关文档 | 可选 | 可选 | 清单、跨 CBB 架构等 |

**简单 CBB**：完成第 1~8、13 章即可；第 9~12 章可省略，也可按需补充。

**复杂 CBB**：在第 1~8、13 章之外，必须完成第 9~12 章。微架构、数据流、状态机的具体内容由模块功能决定，规范只要求说明这些维度，不规定固定写法；如果模块没有状态机，第 10 章写“不适用”并说明原因。

复杂 CBB 的判定见 [开发流程指南 §4.1](../development-guide.md#41-复杂度分级)：时钟域 ≥ 2 或含 CDC、状态 ≥ 4、端口 > 20、含 FIFO / 仲裁 / 总线协议 / 完整数据通路。

## 3. 一致性要求

- 第 3、4 章的端口/参数必须与 `.sv` 完全一致；评审时逐项核对。
- 复杂 CBB 的第 9~12 章必须与实现一致。
- 端口、参数或时序语义变化时，同步更新本文档和 `cbb-list.md`。
- 缺少文档或文档过期时，CBB 不得标记为“已发布”。
