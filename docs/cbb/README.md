# CBB 文档规范

## 1. 文档落点

每个 CBB 在 `docs/cbb/<module>/` 下维护文档，目录名与 RTL 模块名一致：

```text
docs/cbb/<module>/
├── README.md      # 所有 CBB 必备：功能 / 端口 / 参数 / 使用说明
└── design.md      # 复杂 CBB 必备：详细设计文档
```

- CBB 进入开发时创建文档目录，不预先建空目录。
- 文档与 RTL 同一次变更提交；文档与实现不一致视为未完成。
- 简单 CBB 只需 `README.md`；复杂 CBB 必须同时有 `README.md` 和 `design.md`。
- 模板：[`_template/README.md`](_template/README.md)、[`_template/design.md`](_template/design.md)。

## 2. `README.md` 必备内容

所有 CBB 的 `README.md` 至少包含以下章节：

| 章节 | 必须回答的问题 |
|---|---|
| 基本信息 | CBB ID、模块名、类别、状态、版本、维护人、更新时间 |
| 功能与范围 | 做什么、不做什么、典型使用场景 |
| 端口表 | 名称、方向、位宽、时钟域、说明；valid-ready 信号的角色 |
| 参数表 | 名称、类型、默认值、合法范围、说明；参数约束 |
| 使用说明 | 时钟/复位要求、握手规则、延迟/吞吐、反压行为、初始化、例化示例 |
| 复位与 CDC | 复位类型与释放方式；是否有跨时钟域、采用什么同步策略 |
| 限制与注意 | 已知限制、不可用法、性能边界、依赖条件 |
| 验证状态 | 自检结果、TB/SVA 覆盖点、跑过的仿真器、未跑项 |
| 版本记录 | 版本、日期、变更内容、兼容性说明 |

> 模块头注释只是代码内的快速摘要，**不能替代** `README.md`。端口表、参数表和使用说明以 `README.md` 为准。

## 3. `design.md` 必备内容（仅复杂 CBB）

复杂 CBB 的详细设计文档至少包含：

1. 功能与定位、与已有 CBB 的复用/依赖关系
2. 模块划分、层级树、框图和数据流向
3. 接口与参数（可与 `README.md` 引用，但必须给出微架构相关约束）
4. 数据通路与微架构、关键寄存器/存储体
5. 状态机（enum、状态转移、编码方式）
6. 时序、流水线、延迟/吞吐和反压路径
7. 复位与 CDC 策略
8. PPA 权衡（关键路径、面积、功耗、ICG 策略）
9. 验证计划（SVA 断言清单、参数校验、定向/随机场景）
10. 风险、限制与未覆盖项
11. 变更记录

## 4. 一致性要求

- `README.md` 的端口/参数必须与 `.sv` 完全一致；评审时逐项核对。
- `design.md` 的模块划分、状态机、复位/CDC 方案必须与实现一致。
- 端口、参数或时序语义变化时，同步更新 `README.md`、`design.md` 和 `cbb-list.md`。
- 缺少对应文档或文档过期时，CBB 不得标记为“已发布”。
