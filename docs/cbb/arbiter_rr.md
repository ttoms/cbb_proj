## 2. 功能与范围 [M]
- **功能**：轮询（round-robin）仲裁，从 `ptr` 指向的索引开始扫描请求位图，输出独热授权。
- **不包含**：不做加权、不做 QoS 分组、不做授权寄存、不做背压；不处理请求撤销。
- **典型场景**：多通道公平共享单端口、`arbmux` / `strmux` 的默认仲裁核、轮询仲裁作为 `arbiter_wrapper` 的 `ARB_RR` 分支。

## 3. 端口表 [M]
| 端口 | 方向 | 位宽 | 时钟域 | 说明 |
|---|---|---|---|---|
| `clk` | input | 1 | - | 时钟 |
| `rst_n` | input | 1 | `clk` | 异步复位、同步释放，低有效 |
| `req` | input | `N` | `clk` | 请求位图，每路 1 bit |
| `gnt` | output | `N` | `clk` | 独热授权，最多一路有效 |
| `gnt_vld` | output | 1 | `clk` | 有授权时为 1，等价于 `OR(req)` |

无 valid-ready 握手；`gnt` 为组合输出，`req` 在授权周期内必须保持有效。

## 4. 参数表 [M]
| 参数 | 类型 | 默认值 | 合法范围 | 说明 |
|---|---|---|---|---|
| `N` | `int` | `4` | `N >= 1` | 请求路数 |

参数约束：`N >= 1` 由 `arbiter_rr.sva` 检查；内部索引位宽 `IDX_W = (N > 1) ? $clog2(N) : 1` 自动派生。

## 5. 使用说明 [M]
- **时钟/复位**：单时钟；`rst_n` 异步拉低、同步释放，建议由 `rst_sync` 产生。复位后 `ptr=0`，即索引 0 最先获得优先权。
- **延迟/吞吐**：`req → gnt` 纯组合；每拍最多一个授权，持续请求时 1 次授权/拍。
- **反压**：无。授权方（`arbmux` / `strmux`）负责在未握手时保持请求并处理反压。
- **初始化**：复位清 `ptr`；无请求时不更新 `ptr`。
- **限制**：`gnt` 为组合输出；只做仲裁，不保证授权对应的数据通道已准备好。

```systemverilog
arbiter_rr #(
    .N (4)
) U_ARB (
    .clk     (clk),
    .rst_n   (rst_n),
    .req     (req),
    .gnt     (gnt),
    .gnt_vld (gnt_vld)
);
```

## 6. 复位与 CDC [M]
- **复位**：`ptr` 是控制类寄存器，用 `dffr` 异步复位到 0；无数据通路寄存器，无复位树开销。
- **CDC**：无。单时钟模块，所有逻辑同域。

## 7. 限制与注意 [M]
- 授权后 `ptr` 立即指向被授权索引的下一路，同一拍不能再改选，因此单拍只产生一个授权。
- 请求位图在授权周期内必须稳定；组合撤销请求可能导致 `gnt` 抖动，需上游保证请求有效。
- `N=1` 时 `ptr` 恒为 0，`gnt_vld == req[0]`。
- 不做请求锁存；若上游请求是脉冲，需在 `arbiter` 外层用 `req` 保持寄存器。

## 9. 微架构与数据流 [C]
- **模块划分**：单模块，无子模块；一个组合扫描块 + 一个 `dffr` 指针寄存器。
- **框图**：

```text
              +---------------------------+
  req[N] ---->| 从 ptr 起循环扫描 N 路     |----> gnt[N]（独热）
              | 首个 req=1 的索引胜出      |----> gnt_vld = |gnt
              +-------------+-------------+
                            |
                        gnt_idx
                            |
                  +---------v---------+
                  | nxt_ptr = idx+1   |
                  | （回绕到 0）       |
                  +---------+---------+
                            |
                     +------v------+
                     | U_PTR dffr  |  en = gnt_vld
                     +------+------+
                            |
                           ptr
```

- **数据流**：
  - 组合扫描：`i` 从 0 到 `N-1`，索引 `idx = (ptr + i) % N`；遇到首个 `req[idx]=1` 且尚未授权时置 `gnt[idx]=1`，记录 `gnt_idx`。
  - 指针更新：授权有效时 `nxt_ptr = (gnt_idx == N-1) ? 0 : gnt_idx + 1`；无授权时 `en=0`，`ptr` 保持。
  - 输出：`gnt` 直接由组合扫描产生，`gnt_vld = |gnt`。
- **关键寄存器/存储体**：

| 名称 | 用途 | 复位 | 更新条件（en） |
|---|---|---|---|
| `ptr` | 下一轮优先起始索引 | `dffr` 复位 0 | `gnt_vld` |

- **关键设计决策**：用“指针 + 循环扫描”而不是旋转请求位图，逻辑直白、面积小；`ptr` 只在授权时更新，保证严格轮询且无请求时零翻转。`gnt_idx` 由扫描过程直接产生，`nxt_ptr` 只是一级加一/回绕，不额外维护计数器。

## 10. 状态机 [C]
不适用。模块只有一个指针寄存器，没有多步控制序列，也不存在非法状态编码；指针值域由 `% N` 保证始终合法。

## 11. 时序、流水线与 PPA [C]
| 场景 | 延迟 | 吞吐 | 说明 |
|---|---|---|---|
| 正常授权 | 组合（0 拍） | 1 次授权/拍 | `req → gnt` 组合路径 |
| 无请求 | 组合 | 0 | `ptr` 保持 |

- **关键路径/流水线**：`ptr → 循环扫描 → gnt` 为组合路径，扫描深度 `N`，综合后是 `N` 级优先级 mux；`N` 较大时可在 `arbiter_wrapper` 外层加 `reg_slice` 切分，不在本模块内插流水。
- **反压路径**：无。仲裁核不感知下游 ready。
- **面积/功耗**：`IDX_W` 个触发器 + `N` 位组合扫描；无请求时 `ptr` 的 `en=0`，时钟可被门控。面积随 `N` 线性增长。
- **取舍**：组合授权换 0 拍延迟和最小面积；不做授权寄存，避免多一拍延迟和额外状态。

## 12. 风险与未覆盖项 [C]
- **风险**：组合 `gnt` 依赖 `req` 稳定；`req` 毛刺会直接传到 `gnt`。`ptr` 更新与授权同拍完成，若上游在同一拍撤销请求，授权已发出但数据可能无效。
- **限制**：单时钟；无背压；无加权/QoS；`N` 较大时组合路径变长。
- **未覆盖项**：`N > 8` 的大位宽、`req` 为 X/Z 的仿真、门级仿真与综合时序/面积、形式化验证。
